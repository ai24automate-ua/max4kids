# Max4Kids (velomaks.com.ua) — каталог: Airtable (контент) + Salesdrive YML (ціни/залишки)

## Перш ніж деплоїти

1. **Перевипусти Airtable-токен**, якщо він десь світився поза бекендом (у чаті, скріншоті, git-історії). Компрометований секрет — завжди compromised, "ніхто не бачив" не рахується.
2. Токен ставиться **тільки** в env-змінну бекенду (`AIRTABLE_TOKEN`), ніколи в `js/*.js` чи `index.html`.

## Структура

```
index.html                     — сторінка (Alpine.js)
js/config.js                   — публічні налаштування (без секретів)
js/airtable-client.js          — фетч контенту через /api/products
js/salesdrive-yml.js           — фетч + парсинг YML через /api/feed
js/catalog.js                  — злиття Airtable + YML, розрахунок Stage 1/2
js/app.js                      — Alpine-компонент catalogApp()
server/api-proxy-example.js    — приклад бекенд-проксі (Node/Express)
```

## Як це працює

- **Stage 1** (товару ще немає в Salesdrive, або ціна/залишок = 0): картка показує `title`, `short_description`, `default_photo` з Airtable. Кольори приховані. Замість ціни — "Ціну буде уточнено". Кнопка — "Повідомити про надходження", відкриває форму збору контактів.
- **Stage 2** (в YML знайдені оффери з `price > 0` і `qty > 0` для даного `parent_crm_code`): з'являються кольорові перемикачі, актуальна ціна/знижка, кнопка "Купити".
- Перехід визначається автоматично в `CatalogMerge.merge()` — нічого вручну перемикати не треба, досить щоб Salesdrive почав віддавати позиції.

## Як зіставляються Airtable і YML

`parent_crm_code` в Airtable — просте слово чи фраза (напр. "Мрія" або, краще, "Мрія 2025"). У YML модель матчиться **пошуком цього коду як підрядка в `<name>` офера** — саме так влаштовано в цьому проєкті (довгі описові назви типу "Санки-трансформер дитячі Мрія 2025 колір: рожевий рейки-рожево-ванільні ТМ Veloz").

Наслідки цього підходу:
- **Роби коди специфічними.** Якщо в тебе одночасно є модель "Мрія" і "Мрія 2025", коротший код підхопить обидва офери. Скрипт це виявляє і пише `console.warn` з переліком неоднозначних збігів — перевіряй консоль браузера після першого запуску на реальному фіді.
- Коди коротші за 3 символи ігноруються (`YML_MATCH_MIN_CODE_LENGTH` в config.js) — занадто ризиковано матчити по 1-2 літерах.
- Колір спершу шукається в `<param name="колір">`, якщо такого немає — витягується з тексту назви за патерном `колір: XXX` (бере перше слово після двокрапки).

Якщо твій фід все ж структурований інакше (окремий `<param>` з кодом моделі, або код у `vendorCode`) — постав `YML_MATCH_STRATEGY: 'param'` або `'vendorCode-prefix'` в `js/config.js`.

## Бекенд-проксі

`server/api-proxy-example.js` — робочий приклад на Express, але це ілюстрація підходу, не production-готовий сервіс. В реальному деплої:
- або постав цей самий код у Vercel/Netlify Function / Cloudflare Worker,
- додай кешування відповіді Airtable на самому проксі (не тільки на клієнті).

`submitOrder()` у `js/app.js` відправляє заявку на `/api/order` (Netlify Function `netlify/functions/order.js`), який форвардить її в SalesDrive CRM через офіційний метод API "Додавання заявок" (`POST https://{домен}.salesdrive.me/handler/`). Потрібні env-змінні `SALESDRIVE_DOMAIN` і `SALESDRIVE_FORM_KEY` — див. `DEPLOY.md`.

## Важливе обмеження щодо SEO

`updateSeoForProduct()` в `js/app.js` міняє `<title>`/`<meta description>`/canonical при відкритті модалки "Детальніше" — це **UX-фіча**, не заміна серверного SEO. Google виконує JS з затримкою і не завжди довіряє canonical, вставленому через JS. Якщо позиції товарних сторінок у пошуку критичні — потрібні окремі SSR/SSG-сторінки на `/{slug}`, а не тільки клієнтська модалка на одній лендинговій сторінці.

## Примітка щодо цієї версії

Цей `index.html` збудований поверх твого реального продакшн-файлу (з лого,
брендовими кольорами `#FF914C`/`#00BBFF`, контактами velomaks.com.ua,
Instagram/TikTok у футері) — не поверх старішого шаблону.

Стара клієнтська логіка `products.json` (`transformRawFeed`, `extractVariant`,
`colorHexMap` — парсинг кольору з тексту назви прямо в браузері) видалена й
замінена на `js/salesdrive-yml.js`, який робить те саме, але отримує XML через
`/api/feed` (Netlify Function), а не статичний JSON-файл із репозиторію.

## SEO-сторінки товарів (SSR, не тільки Airtable+JS)

Крім SPA-каталогу на `/`, кожен товар тепер має власну справжню
серверну сторінку `/product/{slug}/` — рендериться "наживо" з Airtable+YML
на кожен запит (Netlify Function `netlify/functions/product-page.js`),
з реальними `<title>`, `<meta description>`, `canonical`, JSON-LD Product
у HTML ще до виконання JS. Це те, що Google реально зможе проіндексувати.

Додатково:
- `/sitemap.xml` — автоматично перелічує всі товари з Airtable
- `/robots.txt` — вказує на sitemap

**Обов'язкова env-змінна:** `SITE_URL` (напр. `https://max4kids.com.ua`) —
без неї за замовчуванням використовується `https://max4kids.netlify.app`.
**Коли купиш реальний домен — онови тільки цю змінну в Netlify** і
задеплой заново; в коді (`product-page.js`, `sitemap.js`, `robots.js`)
нічого міняти не треба, вони всі читають один і той самий `SITE_URL`.
