# Деплой на Netlify (Git → GitHub → Netlify)

Розраховано на те, що Netlify Functions заміняють `server/api-proxy-example.js` —
той файл більше не потрібен для цього шляху деплою, він лишається в проєкті
як приклад для випадку, якщо колись деплоїтимеш на щось інше (Vercel, свій сервер).

## Крок 0. Що має лежати в репозиторії

Переконайся, що в тебе є всі ці файли/папки (все, що я віддав тобі раніше):

```
index.html
netlify.toml
js/
  config.js
  airtable-client.js
  salesdrive-yml.js
  catalog.js
  app.js
netlify/
  functions/
    products.js
    feed.js
```

## Крок 1. Постав Netlify CLI (необов'язково, але зручно для перевірки перед пушем)

```bash
npm install -g netlify-cli
```

Якщо не хочеш ставити CLI — пропусти, деплой все одно спрацює через сайт Netlify.

## Крок 2. Створи репозиторій на GitHub

1. Зайди на github.com → New repository → назви, наприклад, `max4kids-catalog`.
2. Не додавай README/gitignore на цьому кроці, якщо в тебе вже є локальна папка з файлами — простіше буде запушити без конфліктів.

## Крок 3. Заінітізуй git локально і запуш

У теці з файлами проєкту:

```bash
git init
git add .
git commit -m "Каталог: Airtable + Salesdrive YML, Netlify Functions"
git branch -M main
git remote add origin https://github.com/ТВІЙ_НІК/max4kids-catalog.git
git push -u origin main
```

Заміни `ТВІЙ_НІК` на свій логін GitHub. Git попросить авторизуватись —
через браузер або токен, залежно від того, як у тебе налаштовано git.

## Крок 4. Підключи репозиторій до Netlify

1. Зайди на app.netlify.com → **Add new site → Import an existing project**.
2. Обери **GitHub**, авторизуй доступ, якщо просить.
3. Знайди й обери репозиторій `max4kids-catalog`.
4. На екрані налаштувань білда:
   - **Build command** — залиш порожнім (сайт статичний, збірка не потрібна).
   - **Publish directory** — `.` (корінь репозиторію; це вже прописано в `netlify.toml`, Netlify підхопить сам).
5. Поки що **не тисни Deploy** — спершу задай env-змінні (крок 5), інакше перший деплой одразу впаде в помилку 500 при зверненні до Airtable.

## Крок 5. Додай секретні env-змінні

В Netlify: **Site settings → Environment variables → Add a variable**. Додай чотири:

| Ключ | Значення |
|---|---|
| `AIRTABLE_TOKEN` | твій **новий** (перевипущений) Airtable Personal Access Token |
| `AIRTABLE_BASE_ID` | ID бази, виду `app...` (береться з URL твоєї бази Airtable) |
| `AIRTABLE_TABLE_NAME` | назва таблиці, за замовчуванням `Products` — постав, якщо в тебе інша |
| `SALESDRIVE_YML_URL` | публічне посилання на твій YML-фід Salesdrive |
| `SALESDRIVE_DOMAIN` | піддомен кабінету SalesDrive, напр. `yourcompany` (без `.salesdrive.me`) |
| `SALESDRIVE_FORM_KEY` | ключ форми з кабінету SalesDrive → Установки → Загальні налаштування і інтеграції → Інші сервіси → API → Додавання заявок — саме через нього `/api/order` створює заявки в CRM |

Це і є той самий "бекенд-проксі, який тримає токен" — тільки Netlify Functions виконують цю роль замість окремого сервера. Токен звідси ніколи не потрапляє в браузер.

## Крок 6. Задеплой

Тисни **Deploy site**. Зачекай 30–60 секунд, поки Netlify збере й запустить функції.

## Крок 7. Перевір, що функції реально працюють

Відкрий у браузері (заміни `твій-сайт` на реальний піддомен Netlify):

```
https://твій-сайт.netlify.app/api/products
https://твій-сайт.netlify.app/api/feed
```

- `/api/products` має віддати JSON з масивом `records` — це твої товари з Airtable.
- `/api/feed` має віддати сирий XML — це твій YML-фід.

Якщо бачиш `{"error": "..."}` замість даних — значить, десь неправильно введена env-змінна (найчастіше: помилка в `AIRTABLE_BASE_ID` або токен без прав на цю базу). Виправляєш у Site settings → Environment variables → редагуєш значення → **Deploys → Trigger deploy** (env-змінні підхоплюються тільки при новому деплої, "на льоту" не оновлюються).

## Крок 8. Відкрий сам сайт і перевір консоль браузера

1. Відкрий `https://твій-сайт.netlify.app/`.
2. Натисни F12 → вкладка Console.
3. Подивись, чи немає помилок і чи немає попереджень `[SalesdriveYml] Неоднозначний збіг...` — якщо є, повертайся до `parent_crm_code` в Airtable і роби коди специфічнішими (див. README.md).
4. Перевір картку товару, що вже є в YML з ціною — має бути Stage 2 (кольори, ціна, "Купити"). Перевір товар, якого ще немає в YML — має бути Stage 1 ("Ціну буде уточнено", "Повідомити про надходження").

## Подальші зміни

Кожен `git push` в `main` після цього автоматично тригерить новий деплой на Netlify — окремо нічого запускати не треба.

## Підключення власного домену (коли будеш готовий)

**Site settings → Domain management → Add a domain**, далі Netlify підкаже, які DNS-записи виставити в реєстратора домену. Це вже не пов'язано з кодом — став, коли буде треба, не раніше, ніж переконаєшся, що каталог на `*.netlify.app` працює коректно.
